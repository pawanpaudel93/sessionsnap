Install

You need macOS with cmux 0.64 or newer, and the agents you want to restore on your PATH.

On Linux, sessionsnap installs, updates and uninstalls, but saving and restoring don't work yet: cmux on Linux is a different app with a different command line. On macOS, sessionsnap is verified with cmux 0.64.22.

One command installs the latest release:

$ curl -fsSL https://sessionsnap.pawanpaudel.com.np/install.sh | sh

The installer:

  1. Picks the build for your system: one universal binary for macOS (Apple Silicon and Intel), or a static binary for Linux x86_64 or arm64. It needs curl, tar, and shasum or sha256sum.
  2. Finds the latest release on GitHub, or uses SESSIONSNAP_VERSION.
  3. Downloads the archive and its .sha256 file, and stops if the checksum does not match.
  4. Installs sessionsnap into ~/.local/bin (copy, then rename, so a running sessionsnap keeps its old file). Running it again upgrades in place.
  5. Adds that folder to PATH in your shell's startup file (.zshrc, .bash_profile on macOS or .bashrc on Linux, fish's config.fish, else .profile) if it is not there yet.
  6. On macOS, if cmux is on your PATH and a terminal is attached, runs sessionsnap install-cmux, which asks before adding the palette commands; otherwise it says how to run that later. The palette is macOS-only, so on Linux this step is skipped.
  7. Prints the installed version and the next steps.
VariableEffect
SESSIONSNAP_VERSIONInstall this version (for example 0.1.0) instead of the latest.
SESSIONSNAP_INSTALL_DIRInstall into this folder instead of ~/.local/bin (it is created if missing). It must be an absolute path (a leading ~ is expanded) without quotes, $, backquotes, backslashes or control characters.
SESSIONSNAP_NO_CMUX=1Skip the cmux palette step (macOS); the installer only says how to run it later.
 
$ curl -fsSL https://sessionsnap.pawanpaudel.com.np/install.sh | SESSIONSNAP_NO_CMUX=1 sh

Manual download

Each release has one archive per platform, each with a .sha256 file next to it. The archive holds the sessionsnap binary.

  • sessionsnap-X.Y.Z-universal-apple-darwin.tar.gz (macOS, Apple Silicon and Intel)
  • sessionsnap-X.Y.Z-x86_64-unknown-linux-musl.tar.gz (Linux x86_64)
  • sessionsnap-X.Y.Z-aarch64-unknown-linux-musl.tar.gz (Linux ARM64)

From source

With Rust 1.96 or newer:

$ cargo install --git https://github.com/pawanpaudel93/sessionsnap

Quick start

$ sessionsnap save work                 # snapshot everything open (new version if "work" exists)
$ sessionsnap show work                 # workspaces and tabs
$ sessionsnap restore work --plan       # what would be reopened
$ sessionsnap restore work              # plan, confirm, reopen what is missing
$ sessionsnap recent                    # agent sessions from the last 24h not open in cmux
$ sessionsnap ui                        # the web UI in the cmux Dock

Every command takes --json (machine-readable output, never prompts) and -y/--yes (answer yes to confirmations). Snapshot names use letters, digits, ., _ and -. A version is written <name>@<v>, for example work@3; without @ it means the latest.

Example output:

$ sessionsnap save work
Saved work v3: 9 workspaces, 29 tabs (+2 tabs, 1 tab moved)
$ sessionsnap restore work --plan
+ create workspace Cascadia (3 tabs)
    + Fix login redirect
    + Review payments PR
    + dev server
~ add to api:
    + Migrate billing tables
= 25 tab(s) already open or skipped
To apply: sessionsnap apply p20261012094107123

Snapshots

CommandDescription
sessionsnap save [name] Save what is open in cmux as a new version of a snapshot. If nothing changed it writes nothing and exits 3. -w, --workspace <ws> (repeatable): only capture these open workspaces; the rest of the snapshot is kept. --from <name>[@v]: copy another snapshot version instead of capturing. -m, --message: the version message (default: a summary of changes, such as +2 tabs, 1 tab moved). --pick: choose or name the snapshot interactively.
sessionsnap listList snapshots with their latest version, workspace and tab counts, time and message.
sessionsnap openList the workspaces and tabs open in cmux now.
sessionsnap show <name>[@v]Show a snapshot's workspaces and tabs: each tab's position, kind (shell or the agent, such as claude) and title.
sessionsnap history <name>List a snapshot's versions.
sessionsnap diff <name>@a <name>@bCompare two versions: workspaces and tabs added (+), removed (-), moved (→) and renamed (~).
sessionsnap prune <name> --keep <n>Delete all but the newest n versions. Asks first.
sessionsnap delete <name>Delete a snapshot and all its versions. Asks first.

Editing

Edits change a saved snapshot, not cmux, and each one is a new version. A tab is <workspace>#<position> (1-based) or <workspace>:"<part of the title>"; a workspace is its name or a unique part of it.

CommandDescription
sessionsnap ws <name> [ws] Edit a workspace: --rename <new>, --color <color>, --index <n> (new position, 1-based), --remove, --add-live <ws> (add a workspace from what is open in cmux now), --from <name>[@v]:<workspace> (copy a workspace from another snapshot), -m, --message.
sessionsnap tab <name> <target> Edit a tab: --rename, --index <n>, --move <ws>, --remove, --cwd <dir>, --session <id> (point it at another agent session). With a workspace as the target: --add-session <id> adds an agent tab, and --add-terminal --cwd <dir> adds a terminal tab (--command, --title optional). --agent <kind> names the agent of a session when no history has the ID, or several do.
sessionsnap edit <name> --batch <file|-> Apply a JSON array of edit operations as one version (- reads stdin). --dry-run shows the result without saving, with the baseVersion it applied to; --base <v> saves only if the latest version is still v (else exit 6). 
$ sessionsnap tab work Cascadia#4 --move "Cascadia Community"
$ sessionsnap tab work Cascadia --add-session <session-id>
$ sessionsnap tab work Cascadia --add-session <id> --agent opencode
$ echo '[{"op":"tab-move","tab":"Alpha#2","to":"Beta"}]' | sessionsnap edit work --batch -

Batch operations: ws-rename {ws,to}, ws-color {ws,color}, ws-index {ws,index}, ws-remove {ws}, ws-add-live {ws}, ws-from {from,ws}, tab-remove {tab}, tab-rename {tab,to}, tab-index {tab,index}, tab-move {tab,to}, tab-add-session {ws,sessionId,agent?,title?}, tab-add-terminal {ws,cwd,command?,title?}, tab-set-cwd {tab,cwd}, tab-set-session {tab,sessionId,agent?}.

Restoring

A restore compares the snapshot with what is open in cmux and makes a plan: workspaces to create, and tabs to add to workspaces that are already open. Tabs that are already open are skipped. You see the plan before anything opens.

CommandDescription
sessionsnap restore [name][@v] Make the plan, ask, then reopen what is missing. --plan (alias --dry-run): only make and print the plan. -w, --workspace <ws> and --tab <ws>#<n> (both repeatable): only these. A tab named with --tab is added to its workspace if that is open, even a shell tab (a full restore adds only missing agent tabs to open workspaces). --pick: choose the snapshot interactively.
sessionsnap apply <plan-id>Apply a plan made by restore or recent. If cmux changed since the plan was made it refuses with exit 6; make a new plan.

How flags are restored

A restored agent tab runs the agent's resume command with the flags it was started with, from cmux's record. Only the flags on the agent's allow-list are saved and passed again; every other flag the agent's command line knows is left out when you save, and save names the flags it left out (never their values). A flag sessionsnap doesn't know at all (not in claude --help or codex --help as of Claude Code 2.1.296 and Codex 0.160.0) leaves out the session, since what follows it can't be read for certain. Short flags may be grouped (-vs read-only) as the agents allow. A Codex -c key on neither list below also leaves out the session, since it may limit Codex; only model_*, hide_agent_reasoning, show_raw_agent_reasoning, file_opener, tui.*, shell_environment_policy.set.* (environment variables) and model_providers.* (a provider's definition, which may hold its token or headers) are left out with just a note, never saved; the note says the provider's settings were not saved. Claude Code flags missing from claude --help (hidden flags, and the teammate flags cmux passes to Claude Code teams) leave out the session, so teammate tabs are not restored.

AgentFlags keptRestricting (also kept, fail closed)
Claude Code--model, --fallback-model, --effort, --betas, --allowedTools, --allowed-tools; --add-dir, --mcp-config, --append-system-prompt-file, --system-prompt-file (paths only); --dangerously-skip-permissions, --allow-dangerously-skip-permissions, --ide, --verbose, --chrome, --no-chrome--permission-mode, --agent, --setting-sources, --max-budget-usd, --disallowedTools, --disallowed-tools, --tools; --settings, --agents, --plugin-dir (paths only: inline JSON leaves out the session); --strict-mcp-config, --restricted, --safe-mode, --disable-slash-commands, --bare
Codex--model, -m, --cd, -C, --add-dir, --dangerously-bypass-approvals-and-sandbox, --search, --oss; -c for model, model_provider, model_reasoning_effort, model_reasoning_summary, model_verbosity--sandbox, -s, --ask-for-approval, -a, --profile, -p, --enable, --disable, --approve-for-me; -c for approval_policy, sandbox_mode, profile, sandbox_workspace_write.*, features.*, shell_environment_policy.inherit, shell_environment_policy.exclude, shell_environment_policy.include_only, shell_environment_policy.ignore_default_excludes
Every other agentnone: a session started with any flag is left outevery flag

Both --flag value and --flag=value work. A kept flag's values are checked too:

  • a name or mode must be one word of letters, digits and -_.:/@,, at most 100 characters;
  • a path flag must hold a path: inline JSON (a value starting with { or [) is left out;
  • no value may hold a credential in a format that can be told for certain: a token with a known prefix (sk-ant-, sk-proj-, sk-svcacct-, sk-admin-, sk_live_, rk_live_, hf_, npm_, xapp-, ghp_, gho_, ghu_, ghs_, ghr_, github_pat_, xox…-, glpat-, AWS AKIA/ASIA plus 16, Google AIza plus 35), a JWT, a URL with a password (scheme://user:pass@host), a Bearer token, an Authorization:, X-Api-Key: or Api-Key: header value. A password typed inside a permission rule or other free text (such as curl -u user:password) is not detected; recognised are token formats, auth headers and URLs with a password.

A value that fails is left out; a flag left with no value goes too, with a note. A flag that limits the agent (the restricting column) is never lost quietly: if it, or any of its values, can't be saved, the tab's agent session is left out: it is saved with its session ID but none of its flags, and the reason in leftOut; save says to resume it by hand, and restore warns and opens a plain shell (or skips the tab while its session is open): resuming without the flag would allow more than you did. An untested agent's session started with any flag is left out the same way. Caveat: cmux 0.65, the version checked, usually records a Claude Code launch without your --settings when it can merge your settings file into its own (that needs Node), so restrictions in that file are not restored; resume such sessions by hand, or pass the restrictions with other flags. Other cmux versions are unverified. A launch that is not a session (Claude Code with --print/-p or --no-session-persistence, or a subcommand such as claude mcp) is left out the same way.

Loading a snapshot applies the same lists and rules, so an older snapshot never shows or passes a flag that is no longer allowed. A tab whose saved flags can't be passed again keeps its session ID but none of its flags, with the reason (leftOut): restore opens a plain shell in a new workspace, or skips the tab in an open one, with the reason (a hand-edited reason that is blank, too long, or holds a control character or a credential reads “its flags were left out; resume it by hand”). A record of every session seen (sessions.json, never pruned) keeps the flags of its newest launch as read from cmux; every live read of cmux writes it (save, and edits that read cmux), never copies or restores. Every restore, recent and edit that puts a session in a tab reads it: once left out, a session stays left out, and otherwise it resumes with its newest flags (with a warning when the tab's own differ). A session seen nowhere resumes with no flags and a warning. Versions written before the allow-list may still hold their flags on disk until you prune or delete them; they are never shown or replayed. The tokens that pick another session are taken out first: the agent's own resume words and resume flags with the old ID, its continue flag, Claude Code's --session-id <id> and --fork-session, Codex's resume|fork <uuid|--last>. A Codex launch that is a subcommand (codex exec, codex review, …) is not a session and is left out.

A tab with an invalid session ID, or an agent sessionsnap does not know, reopens as a plain shell in its folder, with a warning.

JSON and exit codes

With --json every command prints one JSON object and never prompts, so scripts and agents should always pass it and read the result rather than the text output. A failure prints an error object: 

{"error": {"code": "not-found", "exit": 7, "message": "…"}}

When some restore steps fail, restore and apply exit 1 with the normal result (failed and steps[].error), not the error object; so does uninstall (a step with status: "failed"). Argument errors print plain text and exit 1.

ExitCodeMeaning
0okDone.
1errorError, or some restore steps failed.
2cmux-unreachablecmux is not running or not reachable.
3nothing-to-doNo changes to save, or nothing to restore.
4refusedA confirmation was declined or needs --yes.
5unknown-formatUnknown cmux state or snapshot format.
6plan-stalecmux changed since the plan was made.
7not-foundNo such snapshot, version, workspace, tab or plan.

Web UI

sessionsnap ui serves a small page on http://127.0.0.1:47317/ and shows it in the cmux Dock (the right sidebar). The page runs the same commands as the CLI.

  • Snapshots: save what is open, update a snapshot from what is open, delete one.
  • Workspaces: rename (double-click), reorder, remove, drag tabs to reorder or move them, add an agent session or a shell tab, add a workspace from cmux or from another snapshot. Edits are previewed and saved together as one version.
  • History: compare two versions; restore an older one.
  • Restore: tick workspaces and tabs, see what would open, then restore.
  • Recent: agent sessions (Claude Code, Codex) from the last days that are not open in cmux.

It runs while its terminal is open and stops after 30 minutes without use; nothing starts at login. Stop it with Ctrl-C, or close the “sessionsnap UI” workspace. Flags: --port <n> (default 47317), --idle-minutes <n> (default 30), --no-open (serve without showing the page).

The link carries a key after # (…/#t=<key>), which browsers never send to a server. The key lasts as long as the server: each start makes a new one. It never goes on a command line, where other users could read it with ps: cmux opens the page without it, and the key is handed over through cmux's socket. If that fails, the page opens without a key and sessionsnap ui prints the keyed link in its terminal. If the page has no key or an old one, click Reconnect, open that link, or run sessionsnap ui again. In cmux 0.64 the Dock is a beta feature (Settings → Beta Features → Dock); without it the page opens as a normal browser tab.

Palette and skill

$ sessionsnap install-cmux     # palette commands in cmux (asks first, backs up cmux.json)
$ sessionsnap install-skill    # teaches Claude Code to use sessionsnap

install-cmux adds these commands to ~/.config/cmux/cmux.json; run cmux reload-config to load them. --print prints them instead. The palette is for cmux on macOS: on Linux, install-cmux refuses (exit 4) and changes nothing.

  • sessionsnap: Save / update snapshot
  • sessionsnap: Restore snapshot
  • sessionsnap: Recent sessions not open
  • sessionsnap: List snapshots
  • sessionsnap: Open UI

install-skill installs a Claude Code skill at ~/.claude/skills/sessionsnap. It tells Claude to use --json, to show you a restore plan before applying it, and never to schedule saves on its own.

sessionsnap also reads cmux's state file and cmux --json --id-format both tree --all, and matches open tabs to the state file by surface ID. Snapshots are format 2 ("sessionsnap": 2), plain JSON you can read and edit. Files from pre-release builds (format 1) show as “unreadable” until converted; the README says how. When the latest version can't be read, save compares with the newest one that can, says so, and writes a new version; saves at the same moment never lose a version or share a number.

Security

Snapshots are user-editable files whose contents end up as commands in a shell, so:

  • Every word of a restore command is shell-quoted, and session IDs are validated first (UUIDs for Claude Code and Codex).
  • A tab whose flags, ID, folder or command hold a control character (newline, ^C, ESC …) is never run, and an agent record with one is not saved. A resume command with a backslash is not typed into an already open workspace.
  • Environment variables from cmux's state are never stored. Of an agent's flags, only those on its allow-list are saved; every other known flag (--append-system-prompt, -c mcp_servers…, …) is left out, and save names what it left out. A flag sessionsnap doesn't know (--api-key, --header, …) leaves out the whole agent session. Kept values are checked for their kind (inline JSON is not a path) and for known credential formats (see How flags are restored). A password typed inside a permission rule or other free text is not detected; recognised are token formats, auth headers and URLs with a password. A flag that limits the agent (deny rules, sandbox, permission mode, settings) that can't be saved exactly as given leaves out the whole agent session rather than resume it with fewer limits; so does any flag of an agent whose flags are untested. Restore filters older snapshots through the same rules.
  • Snapshot files are readable only by you (folder 0700, files 0600).
  • The web UI listens on 127.0.0.1 only and needs the key from its link (new for each start, never put on a command line). It answers four connections at once (16 more may wait), runs one command at a time, and shows its page in cmux at most once a second.

Updating

$ sessionsnap update --check   # only say whether a newer release exists
$ sessionsnap update           # replace this binary with the latest release

update asks GitHub for the latest release. If you already have it, it prints sessionsnap X.Y.Z is the latest release. Otherwise it downloads the archive for your system into a private temporary folder, verifies its SHA-256, checks that the new binary reports the expected version, then copies it next to the running binary and renames it into place, so a running web UI keeps its old file until you restart it. If any check fails, nothing is changed. --check only reports, for example sessionsnap 0.2.0 is available (you have 0.1.0); run: sessionsnap update.

  • Installed with cargo: update does not replace a binary under cargo's bin folder (exit 1). Run cargo install --git https://github.com/pawanpaudel93/sessionsnap --force, or switch to the installer.
  • No release found (none published yet, or the repository is private): exit 7. If GitHub can't be reached: exit 1. Both messages name the installer and cargo install instead.
  • A folder you can't write to: it suggests running the update as the folder's owner, or reinstalling there with SESSIONSNAP_INSTALL_DIR.

With --json it prints current, latest, updateAvailable and updated, plus run (with --check) or path (after an update). Running the installer again also upgrades in place.

Uninstall

$ sessionsnap uninstall               # lists what it removes and asks first
$ sessionsnap uninstall --keep-data   # keep your snapshots in ~/.sessionsnap

After you confirm (or with -y), uninstall removes:

  • the “sessionsnap: …” palette commands from cmux's cmux.json, after backing the file up next to itself; your other commands and comments stay (if its "commands" array holds comments, this step is skipped and you remove those entries by hand);
  • the Claude Code skill at ~/.claude/skills/sessionsnap, only if sessionsnap wrote it;
  • ~/.sessionsnap (or SESSIONSNAP_HOME) unless you pass --keep-data; a symlink, or a folder holding files sessionsnap did not make, is left alone;
  • the sessionsnap binary. One installed with cargo is left; run cargo uninstall sessionsnap afterwards.

Anything already gone is reported, not an error. It leaves the PATH line the installer added (other tools may use ~/.local/bin) and lists it. Under --json, or without a terminal, it needs --yes; otherwise it refuses with exit 4.
